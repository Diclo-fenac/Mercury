# API Reference

The Mercury platform exposes a REST API for standard HTTP operations and a real-time WebSocket interface for conversational chat, file streaming, and pub/sub events.

---

## 1. REST API Endpoints

All REST routes are prefixed with `/api/v1` and require standard authentication headers where specified.

### Search APIs (`/api/v1/search`)

#### `POST /`
* **Deprecated:** Yes (replaced by `/api/v1/products/search`, but maintained for client compatibility).
* **Request Body:** [`SearchRequest`](file:///home/mium/code/mercury/app/models/requests.py)
* **Response Model:** [`SearchResult`](file:///home/mium/code/mercury/app/models/responses.py)
* **Description:** Executes hybrid search (fuzzy keyword + semantic embeddings) using RRF ranking.

#### `GET /autocomplete`
* **Parameters:** 
  * `q` (string, required): Search query prefix (1-100 chars).
  * `limit` (int, optional): Max results to return (default: `10`, max: `20`).
* **Description:** Returns a list of real-time autocomplete suggestions from the product catalog.

#### `GET /trending`
* **Parameters:**
  * `category` (string, optional): Filter queries by specific product category.
  * `limit` (int, optional): Max results (default: `10`).
* **Description:** Retrieves the trending search queries based on overall frequency and ratings.

#### `POST /image`
* **Request Body:** JSON dictionary containing:
  * `image_data` (string, required): Base64 encoded image string.
  * `search_type` (string, optional): `"similar"` or `"exact"`.
* **Description:** Triggers vision analysis via the Gemini Vision provider, extracts descriptors, and executes visual similarity search.

### Chat APIs (`/api/v1/chat`)

#### `POST /completions`
* **Headers:** `Authorization: Bearer <token>`
* **Request Body:** [`ChatCompletionRequest`](file:///home/mium/code/mercury/app/models/requests.py)
* **Response Model:** [`ChatResponse`](file:///home/mium/code/mercury/app/models/responses.py)
* **Description:** Batch OpenAI-style response endpoint. Performs chat completions with assistant capability.

#### `POST /stream`
* **Headers:** `Authorization: Bearer <token>`
* **Request Body:** [`ChatCompletionRequest`](file:///home/mium/code/mercury/app/models/requests.py)
* **Response Content-Type:** `text/event-stream`
* **Description:** Server-Sent Events (SSE) streaming API. Emits chunks of the assistant response as they are generated by Gemini.

#### `POST /tools`
* **Headers:** `Authorization: Bearer <token>`
* **Request Body:** JSON dictionary containing:
  * `operation` (string, required): `"discover"` or `"execute"`.
  * `tool_name` (string, optional): Name of the tool to run.
  * `parameters` (dict, optional): Parameters dictionary.
* **Description:** Exposes search, variant matching, and personalization utility tools for inspection or isolated executions.

#### `GET /history/{conversation_id}`
* **Headers:** `Authorization: Bearer <token>`
* **Parameters:** `limit` (int, optional), `page` (int, optional).
* **Description:** Retrieves paginated message history for a conversation thread.

## 2. WebSocket Interface (`/ws`)

For persistent real-time interactions, clients establish a WebSocket connection. Messages are transferred as JSON documents structured with an `event` header and a `data` payload.

### Incoming Client Events

#### `user_auth`
Authenticates the socket connection and maps the connection to a specific user.
```json
{
  "event": "user_auth",
  "data": {
    "user_id": "usr_99827",
    "user_name": "John Doe",
    "language": "en"
  }
}
```

#### `join_conversation`
Joins a collaborative pub/sub room for a specific conversation thread.
```json
{
  "event": "join_conversation",
  "data": {
    "user_id": "usr_99827",
    "conversation_id": "conv_44312"
  }
}
```

#### `chat_message`
Sends a message to the assistant (supports text and inline images).
```json
{
  "event": "chat_message",
  "data": {
    "user_id": "usr_99827",
    "conversation_id": "conv_44312",
    "type": "text",
    "message": "find me red sneakers"
  }
}
```

---

### Outgoing Server Events

#### `auth_success`
Emitted by the server after socket authentication passes.
```json
{
  "event": "auth_success",
  "data": {
    "user_id": "usr_99827",
    "user_name": "John Doe",
    "status": "authenticated",
    "features_enabled": true
  }
}
```

#### `typing_indicator`
Emitted to broadcast typing indicators (e.g., when the assistant is generating text).
```json
{
  "event": "typing_indicator",
  "data": {
    "user_id": "assistant",
    "typing": true,
    "conversation_id": "conv_44312"
  }
}
```

#### `chat_response`
Emitted once the assistant finishes generating a response.
```json
{
  "event": "chat_response",
  "data": {
    "success": true,
    "message": "Here are some red sneakers...",
    "message_id": "msg_1719602412",
    "conversation_id": "conv_44312",
    "personalization_reason": "Boosted because red is your preferred color",
    "features_used": {
      "real_time": true,
      "caching": true,
      "personalization": true
    }
  }
}
```
